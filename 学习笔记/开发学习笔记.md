# **ID**：1 **C#中的Mutex静态类实现单实例运行限制**
**标签**：

## 1.定义
- **Mutex**:Mutual Exclusion（互斥体）操作系统级别的一种同步机制，用于确保在多线程或多进程环境下，某一段代码或资源同时只能被一个线程/进程访问。

## 2.机制
- 代码执行，创建了一个名为 Application.ProductName 的互斥体，并成功获取了所有权。程序正常运行。
当用户再次双击运行同一个程序时：
代码再次执行，尝试创建一个同名的互斥体。
操作系统发现这个互斥体已经存在，并且正被前一个进程占用。
此时，new Mutex(true, ...) 会失败（或者抛出 ApplicationException），或者通过后续代码检查 WaitOne() 发现无法获取锁。
开发者通常会在后面加上判断逻辑：如果获取锁失败，就弹出提示（如“程序已在运行中”）并直接 Application.Exit() 退出。

## 使用方法
  ``` c#

  static class Program
{
    [STAThread]
    static void Main()
    {
        bool createdNew;
        // 尝试创建一个带有程序名称的互斥体，并获取所有权
        // createdNew 会返回 true 表示成功创建（说明是第一次运行）
        // 返回 false 表示互斥体已存在（说明程序已经运行过了）
        using (Mutex mutex = new Mutex(true, Application.ProductName, out createdNew))
        {
            if (createdNew)
            {
                // 第一次运行，正常启动程序
                Application.EnableVisualStyles();
                Application.SetCompatibleTextRenderingDefault(false);
                Application.Run(new Form1());
            }
            else
            {
                // 程序已经在运行，可以弹窗提示并退出
                MessageBox.Show("程序已经在运行中，请勿重复打开！", "提示", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            }
        }
    }
}
```

# **ID**：2  **C# 中的 [STAThread] 与 COM 机制**
**标签**：`C#` `WinForms` `WPF` `COM` `多线程`

## 1. 核心结论
在 WinForms / WPF 桌面程序的 `Main` 方法中，**必须**添加 `[STAThread]` 特性。
- **作用**：将主线程设置为 **STA（单线程单元）** 模型。
- **原因**：Windows 的 UI 控件、剪贴板、拖放、文件对话框等底层功能均基于 COM 组件。如果不加此特性，主线程默认为 MTA，会导致上述 UI 交互功能直接崩溃或抛出异常。
- **注意**：该特性仅影响主线程，不影响程序中手动开启的其他多线程。但在多线程中调用 COM 对象仍需注意线程安全。

## 2. 背景知识：什么是 COM？
**COM（Component Object Model，组件对象模型）** 是微软推出的跨语言二进制接口标准，是 Windows 系统的基石（DirectX、UWP API 等均基于此）。

其核心机制建立在三大概念上：
- **接口（Interface）**：COM 对象只暴露接口（纯虚函数集合），隐藏内部实现。所有接口必须继承自基础接口 `IUnknown`。
- **IUnknown 与引用计数**：COM 无 GC（垃圾回收），靠 `AddRef()`（计数+1）和 `Release()`（计数-1）管理内存。计数归零时对象自我销毁。
- **GUID 标识符**：使用 128 位随机数（GUID）为接口（IID）和类（CLSID）命名，确保全局唯一，避免命名冲突。

## 3. 核心机制：Apartment（套间/单元）模型
早期 COM 对象未考虑线程安全，为避免多线程并发修改导致数据错乱，COM 引入了 Apartment 机制：

| 模型                                | 概念比喻       | 特点                                                                  | 适用场景                        |
| :---------------------------------- | :------------- | :-------------------------------------------------------------------- | :------------------------------ |
| **STA** (Single-Threaded Apartment) | 单人办公室     | 所有请求排队由单线程顺序执行，无需加锁，绝对安全但并发低。            | **UI 控件**、剪贴板、文件对话框 |
| **MTA** (Multi-Threaded Apartment)  | 开放式大办公区 | 多线程直接并发访问，要求 COM 对象自身具备极强的并发锁和线程安全处理。 | 后台服务、无状态计算组件        |

## 4. 总结
`[STAThread]` 本质上是告诉 Windows：“我的主线程是一个遵守规矩的单人办公室，请把所有 UI 相关的 COM 请求安全地派发给它。”

**ID**:3 **判断网络情况**
## 1. 案例
- 在程序状态需要用到网络时需要检查网络连接状态决定程序是否打开或者以离线模式打开。
## 2.方案
- 这是一个通用的功能，可以在很多地方用得到，所以可以创建一个静态类：Runtime。写如下方法，用Codetable。不带参的用于启动程序时的网络检查。
  ``` C#
            public static Boolean CheckOnlineStatus()
        {
            bool Online = false;
            try
            {
                Online = _CodeTable.GetOnlineStatus();
            }
            catch (Exception)
            {
                Online = false;
            }

            return Online;
        }

        public static Boolean CheckOnlineStatus(ICodeTableHander codeTableHandler)
        {
            bool Online = false;
            try
            {
                Online = codeTableHandler.GetOnlineStatus();
            }
            catch (Exception)
            {
                Online = false;
            }

            return Online;
        }
  ```
